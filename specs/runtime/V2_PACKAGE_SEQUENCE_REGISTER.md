## Purpose

This register derives a reusable V2 package sequence from the full V1-to-V2 capability coverage matrix. It is not an implementation IAP and does not authorize feature work.

Package status labels:

- COMPLETE_BASELINE: already represented by accepted V2 evidence.
- CURRENT_PLANNING: this planning deliverable.
- CONDITIONAL_NOT_AUTHORIZED: can only become an execution package after later explicit authority.
- EXCLUDED_UNTIL_AUTHORIZED: must not be implemented under current V2 authority.

## Sequence Rules

1. No future implementation package may start directly from V1 evidence.
2. PARTIAL matrix rows require authority before implementation.
3. EXCLUDED rows remain excluded until a later package explicitly reopens them.
4. NEEDS_DECISION rows require a scope decision before contract or implementation planning.
5. UNKNOWN rows require more evidence before any implementation planning.
6. Every package must preserve exact acceptance gates and final git-status reporting.
7. Future package scopes must list allowed files and forbidden files before any change.

## Recommended Next Sequencing Posture

The next valid step is not a feature implementation. The next valid step is a future explicitly authorized scope-authority checkpoint if the owner wants to reopen any matrix row marked PARTIAL, NEEDS_DECISION, UNKNOWN, or EXCLUDED.

Until that happens, the accepted V2 baseline should remain in maintenance mode only.
